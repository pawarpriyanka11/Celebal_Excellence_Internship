# Visual Product Recommendation Engine

An image-based "shop similar" recommendation system, the same idea behind
Flipkart/Amazon/Meesho's visual search: upload a product photo, get back
visually similar items — no text search involved.

Pipeline: **pretrained CNN embeddings → cosine/FAISS similarity → optional
Siamese network fine-tuning (triplet loss) → Streamlit UI**.

Built to run fully on **CPU** — no GPU required (MobileNetV2 backbone,
small ~2,000-image subset, short triplet training).

---

## 1. Setup

```bash
cd fashion-visual-search
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

## 2. Get the dataset

Dataset: [Fashion Product Images Dataset](https://www.kaggle.com/datasets/paramaggarwal/fashion-product-images-dataset) (Kaggle).

**Option A — Kaggle CLI**
```bash
# requires a kaggle.json API token in ~/.kaggle/ (from kaggle.com/settings)
kaggle datasets download -d paramaggarwal/fashion-product-images-dataset -p data/raw --unzip
```

**Option B — manual download**
Download the zip from the Kaggle page above, unzip it, and arrange it as:
```
data/raw/styles.csv
data/raw/images/<id>.jpg
```
(the zip's internal folder names may need flattening to match this — the
scripts only look for `data/raw/styles.csv` and `data/raw/images/`)

## 3. Run the pipeline, in order

```bash
# 1) Build the ~2,000-image subset (8 categories x ~250 images) per the
#    project's subsetting strategy
python src/data_prep.py

# 2) Baseline: extract MobileNetV2 (ImageNet) embeddings + build FAISS index
python src/feature_extractor.py

# 3) Transfer learning + Siamese network fine-tuning (triplet loss)
#    This is the slowest step on CPU - see "Timing expectations" below.
python src/train_siamese.py

# 4) Build embeddings/index from the fine-tuned Siamese model
python src/build_siamese_index.py

# 5) Evaluate: Precision@K, Recall@K, timing, qualitative grids
python src/evaluate.py

# 6) Launch the UI
streamlit run app/streamlit_app.py
```

Step 5 writes `reports/evaluation_results.csv` and
`reports/baseline_qualitative.png` / `reports/siamese_qualitative.png`
(query image + top-K grid) for your report/comparison writeup.

## 4. What each metric means (for your evaluation section)

- **Precision@K** — of the K retrieved items, how many share the query's
  category (proxy for "visually/semantically relevant").
- **Recall@K** — of all relevant items available in the index, how many
  were retrieved in the top K.
- **Inference/embedding time** — printed per query and averaged in
  `evaluate.py`, for the "faster inference using precomputed embeddings"
  outcome.

Ground truth relevance uses `articleType` (e.g. "Casual Shoes" vs
"Sports Shoes") since the dataset has no explicit pairwise similarity
labels — this is a standard, defensible proxy for this dataset and is
worth stating explicitly in your report.

## 5. CPU timing expectations (rough, ~2,000-image subset)

| Step | Approx. time on a modern laptop CPU |
|---|---|
| `data_prep.py` | 1-3 min |
| `feature_extractor.py` (baseline embeddings) | 3-8 min |
| `train_siamese.py` (3 warm-up epochs + 8 triplet epochs, 80 steps/epoch, batch 16) | 20-45 min |
| `build_siamese_index.py` | 3-8 min |
| `evaluate.py` | 1-2 min |

If training feels too slow: lower `IMG_SIZE` to 160, or lower
`EPOCHS_SIAMESE` / `STEPS_PER_EPOCH` in `src/config.py`. The whole
project is driven from that one config file.

```
├── data/
│   ├── raw/              <- put the downloaded Kaggle dataset here

├── src/
│   ├── config.py                 <- ALL paths & hyperparameters live here
│   ├── data_prep.py              <- Step 1: dataset subsetting

│   ├── siamese_model.py          <- Step 6: Siamese architecture + triplet loss
│   ├── triplet_data_generator.py <- on-the-fly (anchor, positive, negative) triplets
│   ├── train_siamese.py          <- Step 5+6: transfer learning warm-up + triplet training
│   ├── build_siamese_index.py    <- embeddings/index for the fine-tuned model

└── requirements.txt
```

## 7. Notes / design decisions

- **MobileNetV2** was used instead of ResNet50 purely for CPU speed;
  swap it in `feature_extractor.py`'s `build_backbone()` for
  `ResNet50`/`EfficientNetB0` if you have GPU access later — the rest
  of the pipeline is backbone-agnostic.
- Embeddings are **L2-normalized**, so cosine similarity = dot product,
  which is what FAISS's `IndexFlatIP` computes — this keeps the FAISS
  and sklearn-cosine code paths numerically consistent.
- The Siamese tower **partially unfreezes** only the last N backbone
  layers (`UNFREEZE_LAST_N_LAYERS` in config) rather than the whole
  network, which is both faster on CPU and reduces overfitting on a
  ~2,000-image subset.
- `evaluate.py` and the Streamlit app both hold out a `query` split
  (15%) from `data_prep.py` so evaluation numbers reflect genuine
  retrieval, not the model finding an image against itself.
